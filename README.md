# 📋 گزارش فعالیت هیئت‌مدیره

بات تلگرام که در **گروه هیئت‌مدیره‌ی شرکت** می‌نشیند، از پیام‌های روزمره‌ی
هر عضو می‌فهمد کجا رفته و چه کاری کرده، و از روی همان‌ها **گزارش روزانه‌ی
هر عضو** و در پایان ماه یک **جدول ۳۰/۳۱ روزه‌ی اکسل** می‌سازد.

هر عضو فقط همان‌طور که حرف می‌زند می‌نویسد:

```
ساعت 9 اومدم پروژه همت
امروز صورت وضعیت رو رسیدگی کردم و کارهای تحویل موقت رو انجام دادم
ساعت 12 رفتم پروژه باغ موزه و اونجا نقشه‌ها رو بررسی کردم و ساعت 7 رفتم
```

و بات این زنجیره را می‌سازد:

| ساعت | محل | شرح |
|---|---|---|
| ۰۹:۰۰–۱۲:۰۰ | پروژه همت | صورت وضعیت رو رسیدگی کردم و کارهای تحویل موقت رو انجام دادم |
| ۱۲:۰۰–۱۹:۰۰ | پروژه باغ موزه | نقشه‌ها رو بررسی کردم |

می‌شود به‌جای عضو دیگری هم گزارش داد؛ کافی است پیام با نام او شروع شود:
«ایدین امروز ساعت ۷ رفت باغ موزه تا ۵ اونجا لوله‌کشی مخزن رو انجام دادن».

---

## ✨ امکانات

- 🧩 **زنجیره‌ی روز**: هر عضو در یک روز چند مقصد دارد؛ هر مقصد یک قطعه با محل،
  شرح، ساعت شروع و پایان.
- 🗣️ **پارسر قطعیِ فارسی** بدون هوش مصنوعی — «رفتم پروژه همت» (جابه‌جایی) از
  «رفتم» (پایان روز) تشخیص داده می‌شود، و «ساعت ۵ رفتم» یعنی ۱۷:۰۰.
- 🧠 **لایه‌ی Gemini** روی پارسر برای روان‌کردن شرح‌ها. اگر سرویس نبود یا پاسخش
  ناقص بود، گزارش از بین نمی‌رود.
- 👤 **شناسایی عضو**: نخستین بار نام و سمت پرسیده می‌شود، بعد از آن هرگز.
- 📊 **خروجی اکسل ماهانه**: برای هر عضو یک برگه با ستون‌های
  «تاریخ | شرح فعالیت‌ها | ساعت شروع | ساعت پایان».
- 🌙 **بستن خودکار روزِ فراموش‌شده**: اگر عضوی «پایان روز» را نزند، روز بعد که
  پیام می‌دهد روز قبلی نهایی و روز تازه باز می‌شود.
- 🎙️ دریافت گزارش با **ویس** (پیاده‌سازی صوت فارسی با Gemini).

## 🧭 معماری

```
تلگرام ──webhook──▶ Next.js روی Vercel ──▶ Postgres (Neon)
                          │
   هر پیام → پارسر قطعی → به‌روزرسانی زنجیره‌ی روز (بدون AI، سریع)
   /report و /close → تحلیل کل روز با Gemini روی همان زنجیره
   /month → اکسل ماهانه، یک برگه برای هر عضو
```

**پشته:** Next.js 16 · TypeScript · grammY · Google Gemini · Drizzle ORM ·
Neon Postgres · ExcelJS

### مدل داده

| جدول | معنی |
|---|---|
| `members` | عضو هیئت‌مدیره (با `user_id` تلگرام؛ عضوِ «فقط نام» هم مجاز است) |
| `member_days` | یک روزِ کاری از یک عضو |
| `activity_segments` | قطعه‌های فعالیت آن روز: محل، شرح، ساعت شروع/پایان |
| `raw_messages` | پیام خام (ردِ ممیزی و مبنای تحلیل دوباره) |
| `conversation_state` | وضعیت گفتگو، با کلید **(chat_id, user_id)** |
| `holidays` | کشِ تعطیلات رسمی تقویم ایران |
| `processed_updates` | جلوگیری از اجرای دوباره‌ی یک آپدیت تلگرام |

## 🚀 راه‌اندازی

### ۱) پیش‌نیازها (همه رایگان)

| مورد | از کجا |
|---|---|
| توکن بات تلگرام | [@BotFather](https://t.me/BotFather) → `/newbot` |
| کلید Gemini | [aistudio.google.com/apikey](https://aistudio.google.com/apikey) |
| دیتابیس Postgres | [neon.tech](https://neon.tech) |
| میزبانی | [vercel.com](https://vercel.com) |

> ⚠️ اگر بات دیگری از همین کد دارید، **هیچ‌کدام** از این چهار مورد را مشترک
> نگذارید؛ به‌ویژه کلید Gemini که سهمیه‌ی رایگانش مشترک است.

### ۲) متغیرهای محیطی

در Vercel و در `.env.local` محلی:

```
TELEGRAM_BOT_TOKEN=        # الزامی
DATABASE_URL=              # الزامی — رشته‌ی اتصال Neon
GEMINI_API_KEY=            # الزامی
PUBLIC_BASE_URL=           # مثل https://x.vercel.app
TELEGRAM_WEBHOOK_SECRET=   # یک رشته‌ی تصادفی
ALLOWED_CHAT_IDS=          # اختیاری ولی توصیه‌شده (خالی = همه مجازند)
GEMINI_MODEL=gemini-flash-latest
GEMINI_FALLBACK_MODEL=gemini-flash-lite-latest,gemini-3.5-flash-lite
HOLIDAY_API_URL=           # اختیاری
```

### ۳) ترتیب کار

```bash
npm install
npm run db:migrate     # ساخت جدول‌ها
npm run build          # همان چیزی که Vercel اجرا می‌کند (مایگریشن + بیلد)
# دیپلوی کنید، PUBLIC_BASE_URL را ست کنید، بعد:
npm run set-webhook
```

بعد در تلگرام `/start` را بزنید.

### ۴) ⚠️ تنظیم گروه (بدون این، بات پیام‌ها را نمی‌بیند)

تلگرام برای بات‌ها **privacy mode** را پیش‌فرض روشن می‌گذارد و بات پیام‌های
متنی معمولیِ گروه را نمی‌بیند — فقط دستورها را. برای اینکه گزارش‌ها دیده شوند:

1. در [@BotFather](https://t.me/BotFather): `/mybots` → بات → *Bot Settings* →
   *Group Privacy* → **Turn off**
2. بات را از گروه **حذف و دوباره اضافه** کنید (تغییر روی عضویت فعلی اثر ندارد).

## 🧱 قواعدی که نباید شکسته شوند

- **وبهوک همیشه ۲۰۰ برمی‌گرداند.** هر پاسخ غیر ۲۰۰ یعنی تلگرام همان آپدیت را
  بی‌پایان دوباره می‌فرستد. حصار خطا در `src/bot/index.ts` و `try/catch` در
  `route.ts` هر دو لازم‌اند. (`bot.catch` فقط در long polling کار می‌کند.)
- **هر آپدیت فقط یک‌بار اجرا می‌شود** (`processed_updates` + `claimUpdate`).
- **درج‌ها دسته‌ای‌اند.** درایور HTTP نئون هر دستور SQL را یک درخواست جداگانه
  می‌فرستد؛ تعداد رفت‌وبرگشت مستقیماً زمان پاسخ بات است.
- **بودجه‌ی هر درخواست:** `maxDuration=60` ثانیه، grammY `timeoutMilliseconds=55`
  ثانیه، سقف کل هوش مصنوعی ۲۰ ثانیه، `timeoutSeconds=20` برای کلاینت تلگرام.
- **هوش مصنوعی هرگز تنها راه استخراج نیست.** پارسر قطعی همیشه اجرا می‌شود و
  پاسخِ ناقصِ AI فقط اجازه‌ی افزودن دارد، نه حذف.
- **شیء خطای grammY هرگز مستقیم لاگ نمی‌شود** (توکن بات داخلش است) — از
  `describeError` در `src/lib/log.ts` استفاده کنید.
- **وضعیت گفتگو per-user است**، نه per-chat؛ وگرنه اعضای گروه روی هم می‌افتند.
- ژورنالِ مایگریشن Drizzle در اسکیمای جدای `drizzle` است؛ برای پاک‌کردن کاملِ
  دیتابیس باید آن اسکیما هم انداخته شود.
